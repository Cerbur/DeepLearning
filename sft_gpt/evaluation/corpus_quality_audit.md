# 当前预训练语料质量审计

审计对象：[训练语料](<.data/corpus/train/>)；同时检查本地验证集。日期：2026-10-20。

## 1. 结论

**格式和基础去重合格；作为小规模中文社交闲聊续写实验可用，但不适合作为当前模型从零学习通用中文能力的唯一预训练语料。** 最重要的问题不是 JSON 损坏或大量全文重复，而是 **数据规模小、来源与文体过窄、短回复/外部上下文依赖强，以及隐私与语义质量筛选不足**。

- 管线冒烟、口语风格学习：可继续作为实验集，但应先处理联系信息。
- 通用中文预训练底座：需要补充多来源、信息性、叙事性及更长的连续文本，不能只反复训练这 5 万条。
- 面向用户的助手：原始熟人聊天并不等于高质量助手回答；预训练后仍需单独设计角色一致、回答可靠的指令训练与评估。

本轮未改动原始语料、训练源码、词表或检查点，未安装依赖、未训练模型。新增的均为审计产物。

## 2. 方法与适用边界

1. 使用标准库严格解析全部 50,000 条训练记录、2,000 条验证记录，统计字符、轮次、重复、关键词候选与潜在联系信息。
2. 固定 seed=20261020，每个训练分片随机抽 6 条，共人工审阅 60 条；另核查风险候选与近重复实例。抽样记录见[随机样本](<evaluation/corpus_audit_samples.md>)。
3. 规范化重复仅用于诊断：NFKC、casefold、保留字母数字。没有将此规则用于改写正文。
4. 近重复规则：规范化后至少 30 字符的 32,055 篇独立文档，字符 4-gram 集合 Jaccard ≥0.8；使用全局稀有度前缀连接筛候选并精确验证。该结果不涵盖更短文本、低于阈值的局部重合或语义改写。
5. token 数按当前默认 HybridTokenizer 的规则（只从 train 建表、min_freq=2、词表上限8192）重新计算，不是从现有磁盘词表或某个检查点推断；结果得到 4,314 项词表。
6. 关键词命中只是**待复核队列**：不能把“代购”“垃圾”等词直接等同广告、辱骂或不合格记录，各类命中可重叠。
7. 本轮未访问原始未清洗归档，未联网核验许可证，也未评估当前检查点生成能力。因此不提供全库语义合格率或清洗前后真实损伤率。

完整指标与成品 SHA256 见[审计统计](<evaluation/corpus_audit_metrics.json>)，复现实现见[审计脚本](<evaluation/audit_train_corpus.py>)。

## 4. 按优先级修改

### P0：先处理潜在个人联系信息

- 训练 **29 条**、验证 **1 条**记录命中大陆手机号格式。
- 已抽查训练前5个候选，存在“电话”“新手机号”“联系方式私我一下”等明确交换联系方式语境；没有验证号码归属或是否仍有效。
- 如[训练分片:2696](<.data/corpus/train/lccc_part_001.jsonl#L2696>)是交换号码，[另一分片:4486](<.data/corpus/train/lccc_part_003.jsonl#L4486>)是直接回复联系方式。审计产物中的对应号码已掩码，不在报告复述。

**修改建议**：对 train/eval 统一检测手机、邮箱、QQ/微信号、详细地址、证件等，结合上下文确认；脱敏或删除高风险整段。不要只匹配这一个正则，也不要把所有长数字当隐私。脱敏后重新去重并重新检查跨集合重合。此项优先于扩大数据或延长训练。

### P1：扩大有效语料规模，调整100%闲聊的配方

当前来源与格式在[manifest:17–27](<.data/corpus/.download_corpus_manifest.json#L17-L27>)可确认：单一 LCCC 来源、纯文本、轮次用换行相连，无角色标签。

当前实际架构为[配置:5–9](<config.py#L5-L9>)中的768宽、13层、2048前馈、512上下文。按本次默认新建词表 V=4314，并考虑[输入输出权重共享](<models/mini_gpt.py#L11-L15>)，静态参数数为：


```text
default_fresh_params = V*768 + 13*(4*768*768 + 3*768*2048 + 2*768) + 768
                    = 95,346,432（约95.35M）
```

这不是已加载检查点的参数报告；[README:9](<README.md#L9>)仍写288宽/8层的旧配置，不能沿用它估计当前训练容量。

**260万 tokens 对从头训练约9535万参数的通用语言模型明显不足**。多轮重放会增加计算暴露量，但不会增加新的主题、语言现象和知识，不能把1000遍同一小集视为26亿多样化tokens。是否已经过拟合需要实际曲线/独立测试，不能仅凭规模断言已发生。

**修改建议**：

- 若目标是通用中文：加入版权与质量可核验的说明、科普、生活知识、叙事和自然连续段落，让LCCC成为混合语料的一部分，而非100%。配比按有效tokens而非文档条数控制。
- 明确增加128–512 tokens连续内容以及较长多轮对话；不要只拼接无关短聊来满足长度指标。
- 先增加一个数量级的多样化数据做固定预算对照，**这只是实验起点，不是95M模型数据已足够的保证**；预算不足时同时考虑较小模型，而不是盲加epochs。
- 若目标仅是闲聊：也应扩充更完整、相关、信息量更高的自然对话，而非照搬百科作为唯一替代。
- 不必因4314词表没达到8192上限就扩大词表：上限不是必须填满的目标，byte fallback也使UNK=0不等于覆盖良好。

### P1：独立做语义质量筛选，而不是只做字符白名单

已确认存在的问题：

- [分片:7](<.data/corpus/train/lccc_part_001.jsonl#L7>)包含地域攻击与侮辱。
- 随机样本中有依赖图片/人物关系的句子，如[样本:55](<evaluation/corpus_audit_samples.md#L165-L166>)“谁帮你拍的呀”“两个手都处境了哒”；另有不完整收尾、错别字、争吵或缺少解释的敷衍回答。这些不一定是采集错误，但不适合直接当通用助手的优质答案。
- 6次以上连续同字符：1,512条（3.02%）；短片段连续重复4次以上：597条（1.19%）。核查既有长串“哈哈”，也有大量句点，因此这是复读/标点审查队列，**不是1,512条都该删**。
- 扩展侮辱语境词候选257条，性相关词候选13条，广告/联系方式关键词候选73条。普通谈论招聘/代购也会命中，不应直接当作对应风险比例。
- 较强脏词词表命中0，但真实侮辱仍存在：仅靠一个敏感词表明显不足。

**修改建议**：先对500–1000条分层抽样标注完整性、轮间相关性、信息量、礼貌/安全、联系方式、复读、依赖图片/外链；据此校准规则，形成保留/降权/剔除三级。严重隐私或明显攻击可整段剔除；普通短答和自然语气词应按整段质量处理，不单独删除一轮再桥接上下文。最低长度仅作候选条件，不要直接把现有27.44%的短文档一刀切删除。

### P1：调整会丢失语义的字符清洗规则

[清洗实现:19–28](<corpus/cleaning.py#L19-L28>)保留汉字、ASCII英数、标点等，将其他字符替换为空格。由规则可验证：全角数字、重音字母、℃、×、部分货币符号、emoji可能丢失；[测试:16–20](<tests/test_corpus_cleaning.py#L16-L20>)还明确要求删除全角数字、重音字母和emoji。

这是**规则本身的损伤风险已确认**，不是说本轮已量化出多少成品被误删。当前成品再次通过cleaner全部不变，只说明幂等，不能证明此前清洗无损。

**修改建议**：

1. 按文本类型做受控Unicode规范化，例如将全角英数规范化后再判断；保存原始版本，避免全局规范化破坏代码或数学表达。
2. 保留常见单位、数学/货币符号及自然口语中的情绪表达，或使用有解释的映射；不要把合法Unicode统称乱码。优先剔除不可见控制/损坏编码，而非删除所有非白名单内容。
3. 下载与训练加载共用同一cleaner，须同步调整，避免重新导入时再次删除。补“１００元、20℃、café、数学表达”的保护测试，并记录修改字符数、空轮及整段丢弃数。
4. 从保留的原始归档重新生成新版本；已删除字符不能从当前JSONL可靠恢复，不要凭空补写。

### P2：改前缀抽样；完善近重复与划分

[下载逻辑:351–365](<corpus/download.py#L351-L365>)达到52,000条有效唯一对话就停止，之后才shuffle。因此seed控制的是此前缀的排序/划分，**不是从完整LCCC随机抽样**。实际来源排序和偏差程度本轮未测。

本轮去重结果：

- train/eval全文及规范化全文交集均0，是已有优点。
- 本次≥30规范化字符、4-gram Jaccard≥0.8规则仅涉及17条训练记录，未检出跨train/eval近重复对。**大面积重复不是当前首要问题。**
- 但9/2000条验证文档（0.45%）含训练集中出现过的≥15规范化字符完整轮次，共11次共享轮次。这是局部重合证据，不是9条完整泄漏，也不能证明所有共享都是同一线程。

**修改建议**：全源reservoir或稳定hash抽样；有原始线程ID时按线程分组，没有时用较长共享轮次/近重复建立候选簇再划分。通用短句不能作为自动合并全部对话的依据。规范化key只用于查重，正文不要删除标点和大小写。

### P2：补独立测试、溯源和可观测性

- 当前eval来自上游train前缀本地划分，并非官方valid/test；适合监控同域续写，不足以证明通用能力。另冻结一个不用于早停的test，按来源/线程/近重复组隔离，覆盖短答、较长多轮、信息性续写及安全场景。
- 比较loss时保持tokenizer和口径一致；生成评估分别记录相关性、通顺性、主题保持、重复、事实与安全，不只看loss/EOS。
- [manifest](<.data/corpus/.download_corpus_manifest.json>)缺少源revision、源SHA256、处理版本、生成时间、许可依据和过滤计数。补这些字段及每来源token配比、长度、拒绝原因统计。浮动main地址加固定seed不保证上游变化后可复现。
- 本轮未核验上游许可。发布/商用前分别核查数据集、原始采集及再分发条件，不能把代码仓库许可自动当数据许可。

## 5. 训练机制上的两个注意点（不应误诊为语料文件坏）

1. [打包:312–337](<data.py#L312-L337>)按每文档BOS/EOS拼流、跨文档固定窗口训练；[attention:27–32](<models/multi_head_attention.py#L27-L32>)只有因果掩码，没有文档隔离。它不是漏加EOS的bug，但约52tokens一段、512tokens一块时，同块常包含约10段无关聊天。以后可对照文档重排/文档感知打包的效果，不能把pack后的512长度当作512长度连贯内容。
2. **仅替换目录后用resume不会使用新语料**：[训练恢复:21–29](<pre_training/trainer.py#L21-L29>)直接复用检查点里的train_texts/valid_texts。从头运行才读取当前目录并建表。要在已有权重上切换新语料应另设计明确的继续预训练流程，不是静默改resume含义。

无角色标签对普通因果LM预训练本身不是格式错误；也不建议把来源不明的多人社交轮次机械轮流标成user/assistant。若目标转为助手，后续应单独做真实角色、训练与推理模板一致、答案质量可控的SFT。

## 6. 推荐执行顺序与验收

1. 保留原始数据/当前版本；先做联系方式与明确高风险整段筛选，train/eval一起处理，复查并记录误报。
2. 修正规范化/字符语义保留策略，同步下载与加载，补损伤保护测试和拒绝原因统计，再从原始数据重新生成版本。
3. 改全源抽样和来源/近重复分组划分，按目标加入多源长短内容，固定独立test。保存来源、许可、版本及校验和。
4. 相同模型、token预算和生成题上比较“原集 / 清洗集 / 多源扩展集”，分辨清洗与分布改动的贡献；数据不足时缩小模型做可承担实验，不靠增加遍数掩盖。

验收至少要求：格式/编码/空文档错误为0；高风险联系信息候选全部有处理或复核记录；全文和高相似度跨集合重合为0或有明确例外；各来源tokens、长度、过滤与人工抽检结果可追溯。语义准确率/生成分数必须靠独立评估，不把正则命中比例当作合格率。

**总建议：保留有价值的自然口语，但将当前LCCC短聊子集从“全部预训练数据”降为“经过脱敏和质量分层的一个来源”；优先补规模与分布，而不是只调大epochs或一刀切删除短句。**
